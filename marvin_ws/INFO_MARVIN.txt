Inicializar la Jetson de Marvin-------------------------------------
Conectarse por medio de wifi a Marvin_Net
ssh marvin@192.168.5.10

Emparejar la hora:
sudo date -s "2026-07-6 10:35:20"

Emparejar palanca:
sudo bluetoothctl
power on
agent on
default-agent
pair [MAC]
trust [MAC]
connect [MAC]

Actualizar Código de Marvin (Afuera del docker)---------------------
cd marvin
git pull origin main
# Actualizar dockerfile(Si hay cambios):
cd /marvin
# Reconstruir Docker (puede tomar 5-10 minutos)
./setup_jetson.sh
sudo docker build . -t marvin:latest

./setup_laptop.sh
Crear docker------------------------------------------------------
sudo docker rm -f marvin_master
sudo docker run -it \
  --name marvin_master \
  --net=host \
  --privileged \
  --env="NVIDIA_DRIVER_CAPABILITIES=all" \
  --runtime nvidia \
  -v /tmp/argus_socket:/tmp/argus_socket \
  -v /dev:/dev \
  -v /home/marvin/marvin/marvin_ws:/root/marvin/marvin_ws \
  marvin:latest /bin/bash

Correr Docker
sudo docker start -i marvin_master

Ejecutar código de ROS2 de Marvin------------------------------------
sudo docker ps
sudo docker marvin_master

Compilar:
colcon build --packages-select marvincar_bringup marvincar_vision

futuro organizacion
Sobre organización futura: por ahora tiene sentido dejar marvin_base_driver.py dentro de marvincar_bringup, porque este paquete está funcionando como el arranque del hardware del robot. Más adelante, cuando ya estén integrados base, LiDAR, cámaras, TF, navegación y configuraciones, conviene separar responsabilidades: un paquete marvincar_base_driver para motores/IMU/batería/controladora, paquetes o launch/configs para sensores como LiDAR y cámara, y dejar marvincar_bringup como el paquete que solo “enciende todo” con launch files y parámetros.
